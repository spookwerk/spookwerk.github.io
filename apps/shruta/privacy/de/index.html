Datenschutzerklärung

Version 1.0 — Gültig ab: 22. Juli 2026

Die Kurzfassung: Die Shruta-App sammelt nichts. Deine Aufnahmen, Transkripte und Stimmdaten werden ausschließlich auf deinem Gerät verarbeitet und gespeichert, verschlüsselt mit einem Schlüssel, der aus einem Passwort oder Code abgeleitet wird, den nur du kennst. Shruta hat keine Konten, kein Inhalts-Backend, keine Analytics, keine Tracker und keine Werbe- oder Analytics-SDKs. Nichts verlässt die App, außer du exportierst es ausdrücklich. Wenn du den Support kontaktierst, verarbeiten wir diese Korrespondenz getrennt wie unten beschrieben.

Was auf deinem Gerät passiert

  • Aufnahmen entstehen nur, wenn du sie startest – auf iPhone oder Apple Watch.
  • Transkription und Sprecherlabels laufen vollständig auf deinem Gerät mit lokalen Machine-Learning-Modellen. Modelldateien werden heruntergeladen, wenn sie erstmals benötigt werden; weder Audio noch Text werden zur Verarbeitung irgendwohin gesendet.
  • Speicherung: Jede Aufnahme, jedes Transkript und jedes Stimmprofil wird auf deinem Gerät mit AES-256-GCM verschlüsselt. Der Schlüssel wird mit Argon2id aus deinem Passwort oder Code abgeleitet. Wir sehen weder dein Passwort noch deinen Schlüssel; es gibt kein Konto und kein Zurücksetzen aus der Ferne. Solange der Tresor bereits entsperrt ist, kannst du das Passwort lokal ändern, nachdem dein Gerät bestätigt hat, dass du es bist (Face ID, Touch ID oder Geräte-Code). Kannst du den Tresor nicht mehr entsperren, kann Spookwerk die Inhalte nicht wiederherstellen.
  • Sperre: Die App sperrt sich selbst, sobald du sie verlässt. Entsperren per Face ID / Touch ID ist optional und läuft über iOS; Shruta erhält nur das Ergebnis, nie biometrische Face-ID-Daten.

Stimmerkennung (optional) – biometrische Daten nach Art. 9 DSGVO

Wenn du sie aktivierst, kann Shruta Stimmen wiedererkennen, um in späteren Transkripten Namen vorzuschlagen. Nach der DSGVO gehören Stimmmerkmale als biometrische Daten zu den besonderen Kategorien personenbezogener Daten (Artikel 9). Shruta behandelt sie maximal zurückhaltend:

  • Ausdrückliche Einwilligung (Art. 9 Abs. 2 lit. a): Ohne explizites Opt-in wird nichts gespeichert – die Stimmerfassung ist überspringbar, und das Merken einer anderen Person erfordert eine separate Bestätigung pro Person.
  • Datenminimierung: Shruta behält nur ein abgeleitetes numerisches Stimmprofil (ein Embedding), nicht die Audioaufnahme – sie wird direkt nach der Verarbeitung verworfen.
  • Nur auf deinem Gerät: Stimmprofile werden mit deinem Schlüssel verschlüsselt und nie übertragen. Es gibt keine Telemetrie zu dieser Funktion.
  • Zweckbindung: Profile dienen ausschließlich dazu, Sprechernamen in deinem eigenen Archiv vorzuschlagen – nie zur Authentifizierung, nie geteilt.
  • Löschung mit einem Tipp: Unter Einstellungen → Deine Stimme löschst du dein eigenes Profil („Stimme vergessen") und jede gemerkte Person einzeln, jederzeit.

Apple-Watch-Aufnahmen – Datenfluss

Wenn du eine Aufnahme mit der Apple Watch App machst, wird die Datei lokal auf deiner Watch gespeichert (AAC, im temporären Verzeichnis der App). Sobald du stoppst, wird die Datei zur Übertragung an dein iPhone vorbereitet – über Apples WatchConnectivity-Framework, einen sicheren, rein lokalen Kanal, der nicht über Apple-Server oder das Internet läuft.

Sobald dein iPhone die Zustellung bestätigt, wird die Datei auf der Watch sofort gelöscht. Schlägt die Übertragung fehl (zum Beispiel weil dein iPhone außer Reichweite ist), wiederholt WatchConnectivity den Versuch im Hintergrund automatisch; die Watch behält die Datei, bis das Betriebssystem die Zustellung bestätigt. Wird die Watch-App während einer Aufnahme beendet, wird eine eventuell abgebrochene Audiodatei beim nächsten Start aus dem temporären Verzeichnis entfernt.

Während die Datei auf deinem iPhone darauf wartet, mit deinem Shruta-Schlüssel verschlüsselt zu werden, liegt sie kurz in einer Warteschlange, die durch iOS Data Protection Klasse C geschützt ist (im Ruhezustand mit deinem Geräteschlüssel verschlüsselt, erst nach der ersten Entsperrung zugänglich). Sobald dein Shruta-Schlüssel verfügbar ist (nach Entsperren der App mit Code oder Biometrie), wird die Datei mit AES-256-GCM unter diesem Schlüssel versiegelt und die unverschlüsselte Kopie gelöscht.

Auf deiner Watch werden Dateien im temporären Verzeichnis nur dann im Ruhezustand mit watchOS Data Protection Klasse C verschlüsselt, wenn du auf der Watch einen Code festgelegt hast. Die Shruta-Watch-App zeigt auf dem Aufnahmebildschirm einen Hinweis, wenn kein Code festgelegt ist.

Die Exportgrenze

Nichts verlässt Shruta, außer du exportierst es ausdrücklich. Über das Teilen-Menü – unter der Überschrift „Das verlässt Shrutas Verschlüsselung" – kannst du ein Transkript kopieren oder als PDF oder Text teilen. Ab diesem Moment liegt die exportierte Kopie außerhalb von Shrutas Schutz. Kopierte Transkripte nutzen einen rein lokalen Zwischenablage-Eintrag, der nach wenigen Minuten abläuft und nicht in die Universelle Zwischenablage gelangt.
